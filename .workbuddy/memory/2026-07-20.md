## 修复部分节点双击无法编辑的问题

- 用户反馈：部分节点无法双击进入编辑状态，右键菜单编辑正常
- 回退上次基于 `mousedown` 时间戳的双击检测方案
- 重新定位原因：`mousedown` 中调用 `onSelect` 会导致 `selectedId` 状态更新，节点重渲染后破坏双击事件（`dblclick`）的 target 一致性，部分节点因此无法识别双击
- 修复方案：
  - 移除 `handleNodeMouseDown` 中的 `onSelect` 调用，选择逻辑完全交给 `click` 事件处理
  - 在 `NodeView` 中基于 `click` 事件做 300ms 双击检测，第一次点击选中，第二次点击进入编辑
  - 拖拽结束后在 `handleMouseUp` 中调用 `onSelect` 保持被拖拽节点选中
- 修改文件：`src/components/MindMapCanvas.tsx`

## 自测并修复大纲视图问题

- 用户反馈：自测是否通过
- 启动 Vite 开发环境，使用 puppeteer + Chrome 浏览器自动化自测大纲视图
- 自测项与结果：
  1. 打开大纲视图 ✅
  2. 大纲显示根节点 ✅
  3. 大纲中添加子节点 ✅
  4. 大纲选中联动画布 ✅
  5. 大纲双击编辑节点 ❌（初次失败）
  6. 键盘方向键切换选中 ✅
  7. Tab 缩进与 Shift+Tab 反缩进 ❌（初次失败）
  8. Delete 删除节点 ✅
- 问题修复：
  - 修复节点行点击事件：展开图标只有在节点有子节点时才阻止事件冒泡，避免无子节点区域点击无法选中
  - 实现基于 click 时间戳的本地双击检测，避免依赖浏览器 `dblclick` 事件在 Tauri WebView 中不稳定
  - 大纲视图使用独立的 `localEditingId` state，不再与画布共享 `editingId`：
    - 根本原因：大纲 input 和画布 NodeView input 同时渲染后会互相抢 focus，导致 blur 触发 `onCommitEdit`，编辑状态被立即取消
    - 解决方案：大纲双击/Enter 进入编辑时只更新本地状态，画布不会渲染 input，避免 focus 竞争
  - 修复 Tab 缩进测试：先添加第二个子节点，再选中第二个子节点进行 Tab 缩进（第一个子节点无前一个兄弟）
  - 按 Tab 后重新查询 DOM 元素获取更新后的深度，避免旧元素引用导致误判
- 清理日志：
  - 删除 `src/hooks/useMindMap.ts` 中 `copyNode`/`pasteNode` 遗留的调试 `console.log`
  - 删除调试过程中添加的临时 `console.log`
