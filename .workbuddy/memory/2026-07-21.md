# 2026-07-21 工作日志

## 修复撤销/重做历史栈的两个 bug

- 背景：便签墙自测（`verify_stickywall.mjs`）发现 Ctrl+Z 无法恢复被删除的卡片；进一步排查发现该 bug 影响所有节点/卡片操作的撤销重做
- Bug 1：历史栈压入的状态错位一位
  - 原因：`useEffect` 中 `setHistory((prev) => [...prev, prevDataRef.current])` 在 updater 里读取 ref，而 updater 可能延迟到下次渲染才执行，此时 `prevDataRef.current` 已被更新为新状态，导致压入的是新状态而非前一个状态
  - 修复：先把快照存入局部变量再调用 `setHistory`
- Bug 2：redo 永远恢复不到撤销前的状态
  - 原因：历史栈只保存「前一个状态」，当前状态从不在栈中，`history[historyIndex + 1]` 拿到的是刚撤销到的同一个状态
  - 修复：重构为完整状态序列——`history` 保存所有状态（含初始状态），`historyIndex` 指向当前状态位置；undo 取 `history[historyIndex - 1]`，新变更时 push 新状态并截断重做尾部；`canUndo` 改为 `historyIndex > 0`
- 修改文件：`src/hooks/useMindMap.ts`
- 自测：`node verify_stickywall.mjs` 16 项全部通过（新建/编辑/拖拽/改色/多选删除/撤销重做/转导图节点/空卡片自动删除）
- 说明：开发服务器（纯浏览器环境）下页面加载有 `transformCallback` 报错，来自 `@tauri-apps/api` 在非 Tauri 环境读取 `window.__TAURI_INTERNALS__`，属预期行为，不影响 Tauri 应用

## 修复节点操作撤销不生效的问题（数据层原地修改污染历史快照）

- 背景：上述自测第 9 组发现「删除子节点后 Ctrl+Z 无法恢复节点」；卡片操作的撤销正常
- 根因：历史栈保存的是 `MindMapData` 引用，而多个数据层函数原地修改了与快照共享的对象：
  - `mindmapEngine.ts`：`removeNode`/`moveNodeToParent`/`reorderNode`/`updateNodeLabel`/`toggleCollapsed`/`insertSubtree` 原地改 `parent.children` 或节点属性
  - `layoutAdapter.ts`：`applyLayoutResult` 原地写节点 x/y/width/height，`applyComputedStyles` 原地改 `node.style`
  - 删除节点时 `parent.children` 被原地改写后，历史快照里的同一对象也被改，撤销取回的快照已经是「删除后」的结构
- 修复：全部改为写时复制——引擎函数把修改后的节点以新对象写回 `data.nodes`；`calculateLayout` 入口复制 nodes 映射，布局结果/计算样式以克隆节点写回
- 修改文件：`src/engine/mindmapEngine.ts`、`src/layout-engine/layoutAdapter.ts`
- 自测：`node verify_stickywall.mjs` 23 项全部通过；`tsc --noEmit` 与 `npm run build` 通过
